# Metadata、版本与开发依赖治理

## 逐字段批准

人工管理的范围包括 `src/metadata.txt` 中全部 userscript 字段（包括添加和删除），以及项目版本。修改前逐项列出字段、现值、拟议值和理由，等待明确批准；批准某字段不授权其他字段。

涉及请求权限的 `@grant`、`@connect` 或匹配范围变更时，先由人工完成 [开发指南](../development.md) 中相关浏览器 smoke test，agent 根据人工提供的普通 fetch 实测结果申请对应字段批准；缺少结果时列为待人工验证，不自行线上探测。挑战页或单个静态样本失败不足以扩大权限。

已批准初始版本为 `0.1.0`，构建以项目版本替换模板中的 `{{VERSION}}`；这不授权后续升级。现有其他 metadata 字段保持不变，除非逐项重新批准。

## 开发依赖

运行时维持零第三方依赖。新增或调整开发依赖前说明用途、拟用版本或范围及为何现有工具不足，取得批准后再修改 manifest 和 lockfile。已有工具及具体版本以配置和锁文件为准，不在文档维护第二份依赖表。

依赖变更审批与安装操作授权是两回事；依赖已经列入配置不代表任意会话可自行安装。

## 获批后的核对

1. 修改维护模板／项目版本／依赖配置，按实际工作同步 lockfile 和构建产物；生成物 header 不是独立编辑源。
2. 按开发指南完成最终检查。交付说明逐项列出实际 metadata／版本／依赖变化；若获准提交，提交前再次核对相关 diff。

模板、项目版本、lockfile 与产物之间必须一致；检查通过不等于批准升级、提交或发布。
