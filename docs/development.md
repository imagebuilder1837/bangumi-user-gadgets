# 开发与交付

## 先确认任务与授权

1. 按 [tracker 指南](agents/issue-tracker.md) 读取当前 ticket、评论、阻塞关系及其父 spec。[#1](https://github.com/imagebuilder1837/bangumi-user-gadgets/issues/1) 是已确认行为规格的唯一维护位置，子票定义交付切片；其中“本轮不实施”等文字指发布规格的当轮，不替代后续明确授权。
2. 本次执行范围以用户明确授权为界。创建规格／ticket、标记 ready、测试通过或构建完成，不自动授权实施、安装依赖、提交、发布或真实启停。有冲突或缺失上下文时报告具体问题，不以现有实现反推新规格。
3. 探索前的领域阅读规则见 [领域指南](agents/domain.md)。外部 selector、协议和样式假设见 [Bangumi 外部事实](external/bangumi.md)；该文档记录观察，不是第二份产品规格。

文档各守其职责：领域词汇表只维护术语；GitHub spec／tickets 维护功能验收；本文维护工程约定与流程；外部文档维护环境事实；[人工治理](agents/metadata.md) 维护 metadata、版本和开发依赖审批。仅保留当前无法从代码轻易获得的约定、理由和陷阱。

## 实施边界

- 保留 Bangumi 宿主 DOM 与运行状态，采用可逆 hide + sibling 接管；不重建 body。入口探测与激活校验分离，宿主可靠边界和所有权恢复按父 spec 验收，不因缺少可选昵称或几何目标而拒绝挂载。
- 与用户帖子等独立组件共存，不修改参考项目、不建立共享运行时。保留捕获阶段同步退出、下一任务重新核对路由后进入的边界；微任务不能替代下一任务。
- 只读取当前 origin 的格纳库主列表，以已确认用户标识精确匹配作者。昵称仅展示，用户名与 UID 不归并；不要为“补全”扩大来源或增加身份查询。
- 同文档内存保存任务、数据和浏览状态；退出清理视图资源而非取消已开始读取或已提交动作。后台完成只更新所属状态，UI 发布重新核对路由和会话，不能重新打开页面或抢焦点。
- JavaScript ESM、零运行时第三方依赖、自包含可读 IIFE。自动启动与显式应用入口分离；入口接受实际浏览器依赖，模型不操作 DOM，视图不自行发请求，外部协议集中封装。不移植帖子的分页 feed、冻结页、持久缓存或多流调度器。
- 优先核对并复用适用的原生 CSS；缺口只增加限定于自有根的最小适配，并向用户说明缺口和新增 CSS。避免重复宿主 ID，保持原站格纳库布局基线，不把帖子单列尺寸当通用规则。

以上是工程护栏；具体路由、恢复、搜索、分类、计数、排序与错误时长等验收值直接读取 spec／ticket，不在本地另存副本。

## 测试 seam 与样本

- 最高 seam 优先使用显式应用入口：提供 jsdom Window、可控 fetch 和计时器，以真实点击、导航和输入观察 DOM、请求、标题与恢复结果。避免逐层 mock 内部模块。
- 纯模型确有独立契约时通过公开接口验证组合结果；不为测试导出私有 helper、不读取内部状态、不绑定偶然模块切分或无关整页快照。
- 同文档重入、迟到响应、外部 DOM 修改和跨功能操作必须经过入口验证，不能仅靠孤立 parser／filter 单测宣称用户流程正确。
- HTML fixture 只保留必要且脱敏的结构：替换动作令牌、移除认证信息、无关脚本及扩展注入，不提交完整私人保存页。异常场景用小样本构造。
- 实际请求测试默认模拟副作用。启停成功规则是父 spec 有意采用的 HTTP 判定；不以测试名义增加登录／正文／业务成功核验或写操作自动重试。

## 测试分工与人工浏览器验收

agent 只执行本地测试与检查，包括模拟请求的应用入口测试、脱敏 fixture、构建及只读 check；不连接或操控真实浏览器，不向线上站点发测试／探测请求。真实浏览器 smoke test、线上读取与启停协议验证由人工完成。agent 提供与本次改动对应的人工验收清单，并根据人工提供的证据记录结果；缺少证据的项目标记“待人工验证”，不能以本地通过替代真实验收。

新增或改变宿主、格纳库或站点样式假设时，agent 先读取外部文档，人工按以下范围完成对应验证：

1. **页面结构**：比较原始 HTML 与运行后 DOM，确认个人导航锚点、focus 节点、真实正文及 footer 边界。登录态和其他组件可能插入兄弟节点；静态样本不能证明共存。
2. **同源读取**：从目标 Bangumi 页面上下文使用普通 fetch 验证当前 origin 的格纳库可读性、主列表完整形态及匿名／登录态差异。挑战页、脚本错误与 CORS 是不同事实；报告实际证据，权限变更遵循人工治理。
3. **样式与时序**：使用现有 Edge 环境验证浅深主题、原站桌面几何、640px 窄屏顺序、键盘／IME、原生 hashchange 和两种组件加载顺序。jsdom 没有真实布局，程序派发事件不能证明浏览器原生任务顺序。不自行新增 Playwright。
4. **真实启停**：必须另获明确的组件目标及启用／停用动作授权。endpoint 即使用 GET 也有副作用，不能当只读协议探测。获准后记录请求参数与实际行为；未获准或未测的项明确保留为待验证。

人工提供的实时结果与外部文档不符时，agent 记录环境、证据类型与范围，更新观察事实；与产品规格不符时先报告冲突，不静默改验收。

## 构建、检查与交付

- 构建生成安装产物，维护源与 metadata 模板是编辑入口；生成物过期通过独立 build 修复，而非手工修改其代码或 header。
- check 必须只读，核对语法、格式、版本／lockfile、metadata、源码与生成物一致性及完整测试。发现过期应失败；格式化和构建分别执行，不让 check 隐式修复。
- 安装依赖须有授权；获准后使用 lockfile 重现环境。审批边界见人工治理，不因工具缺失临时引入依赖。
- 提交信息采用 Conventional Commits。每次提交前在最终变更状态运行 `npm run check`；修复或再次修改后重跑。构建不能代替 check，不声称未运行的检查通过。
- agent 在本地代表宿主 fixture 验证安装产物初始化；真实宿主页初始化与浏览器兼容由人工验收，分别按 ticket 记录。
- 交付报告分列 agent 本地检查、人工提供的浏览器实测结果、待人工验证项及已接受局限。agent 本地任务完成不代表整体验收完成；没有人工证据的真实测试不能标为通过，文档记录也不能冒充线上验收。
