# 维护源导航

行为约束见 [spec.md](spec.md)，外部证据见 [external/bangumi.md](external/bangumi.md)，测试与交付流程见 [development.md](development.md)。本文用于定位改动的责任边界，不逐项复述实现。

从维护源开始修改，不默认读取生成的 `src/index.user.js`；仅为构建排障或交付核验定向检查生成物。

| 改动关注点 | 维护源 | 不可跨越的边界／容易误改之处 |
| --- | --- | --- |
| 启动、路由与会话 | `src/main.mjs`、`src/entry.mjs` | 自动启动与显式入口分离；任务和浏览状态属于用户会话，不属于一次挂载。退出重入、迟到响应与换目标的归属核对不能只放在视图里 |
| 入口、接管与恢复 | `src/host.mjs` | 入口资格不等于正文可接管；恢复的是仍拥有的改动，不是整页快照。新增宿主支持先核对外部证据，不把 fixture 的列 ID 或昵称形态当作通用前提 |
| 外部数据与请求 | `src/garage.mjs` | 响应在此跨越信任边界；完整性失败与分类配置局部失败语义不同。不执行原站脚本，不让视图补抓身份、详情或动作凭证 |
| 作者集合、检索与排序 | `src/model.mjs` | 分类、计数、搜索与排序共享作者集合和分类口径；归类依据原始标签顺序与配置，不从运行后的标签 DOM、统计或样式反推，不操作 DOM |
| 浏览交互与样式 | `src/view.mjs`、`src/host.mjs` | 视图不自行请求；移动、隐藏、高亮不能销毁仍需使用的动作按钮或改变任务归属。CSS 先复用原生规则，祖先依赖与级联缺口的依据只在外部文档维护 |
| metadata 与版本 | `src/metadata.txt`、`package.json` | 不随模块改动顺带调整；字段、版本与开发依赖审批见 [人工治理](agents/metadata.md) |
| 单文件交付 | `scripts/build.mjs`、`scripts/check.mjs`、`src/index.user.js` | 生成物不手工维护，build 与只读 check 分离；构建通过不等于授权提交或发布 |

这些是责任边界，不要求每次新增行为都再拆模块。尤其不要因参考项目已有实现，就引入帖子专用 feed、冻结页、持久缓存、多流调度或共享运行时。

跨边界改动优先通过显式应用入口验证：导航和输入之后观察宿主恢复、请求、标题及可见结果。单独模型测试不能证明重入、共存或后台完成正确；布局、原生事件时序及线上协议按开发指南留给人工验收。
